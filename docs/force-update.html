강제 업데이트 로직

스플래시 화면에서 서버가 판정한 forceUpdate 결과에 따라 앱 진입을 차단하고 스토어로 안내하는 기능의 동작 원리를 정리한다.

이슈 #34 브랜치 feature/034-force-version-update 모듈 FeatureSplash · DomainInterface · Domain · Data · DesignSystem

01 개요

이 앱은 그동안 버전 체크가 전혀 없어서, 서버가 하위 호환을 깨는 변경을 배포해도 구버전 사용자는 계속 앱을 쓰다 정체불명의 오류를 만났다. 스플래시 화면은 세션(Access/Refresh Token) 유효성을 확인해 Home 또는 Onboarding으로 라우팅하는 로직을 이미 갖고 있었는데, 이번 작업은 같은 지점에 버전 체크를 병렬로 추가해서 forceUpdate == true일 때 라우팅 자체를 가로막는다.

판정 기준은 서버의 forceUpdate 플래그 하나뿐이다. 클라이언트는 시맨틱 버전을 비교하지 않고, API 실패·타임아웃 시에는 차단하지 않고 통과시킨다(fail-open).

02 API 계약

/init/versions는 다른 API와 달리 /api/v1 경로가 붙지 않는 루트 엔드포인트다. 그래서 NetworkConfiguration은 기존 baseURL에서 path를 통째로 제거한 rootURL을 별도로 파생시키고, VersionTargetType이 이걸로 baseURL을 override한다.

Request 
GET {rootURL}/init/versions?platform=IOS&appVersion={CFBundleShortVersionString}
Authorization 헤더 없음 — 스플래시 시점엔 토큰이 없을 수 있어 requiresAuthorization = false
Response · AppVersionResponseDTO 
{
  "latestVersion":        "1.0.0",   // 이번 판정 로직엔 미사용 (선택 업데이트 확장 대비)
  "minSupportedVersion":  "1.0.0",   // 동일
  "forceUpdate":          false,     // 유일한 판정 신호
  "updateUrl":            "https://apps.apple.com/app/id000000000"
}

04 스플래시 실행 타임라인

SplashViewModel.start()는 버전 체크와 세션 체크를 async let으로 동시에 띄운다. 최소 노출 시간(2초)이 지나면 세션 체크를 기다리지 않고 버전 체크 결과부터 확인한다 — 강제 업데이트가 필요하면 그 자리에서 즉시 모달을 띄우고, 아직 끝나지 않은 세션 체크는 취소된다. 강제 업데이트가 없을 때만 세션 체크 결과를 마저 기다린다.

05 모달 UI

DesignSystem의 기존 DSModal + momogoModalOverlay를 그대로 재사용한다. onClose와 secondaryTitle을 넘기지 않으면 X 버튼도 보조 버튼도 렌더링되지 않고, 오버레이 자체에 dim 탭 제스처가 없어 닫을 방법이 없다 — 이번 기능이 이 컴포넌트의 첫 실사용 사례다.
