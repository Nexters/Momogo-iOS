온보딩·그룹 UseCase는 서버에 이렇게 연결됐다

UseCase → Repository → DataSource 흐름 자체는 이미 있었지만, Repository의 liveValue가 어디에도 없어 UseCase를 호출하면 크래시가 나는 상태였다. 이번 작업은 그 빈 자리를 채우고, 실제 서버에 붙여보며 드러난 스펙 차이를 바로잡은 기록이다.

UseCase→ Repository→ DataSource→ NetworkClient→ Moya→ 서버

01 이번에 채운 자리

DataSource(Group/User/Auth)는 #Momogo/14에서 이미 실제 네트워크 호출로 완성돼 있었다. 비어 있던 건 그 위의 Repository 한 겹뿐이었다 — Domain은 Data 모듈을 알 수 없으므로, DataSource가 아무리 완성돼 있어도 Repository가 없으면 UseCase는 그걸 쓸 방법이 없다.

03 실제로 붙여보고 나서 알게 된 것들

전부 클라이언트 코드가 서버 스펙을 잘못 가정하고 있던 경우다. curl로 재현해 원인을 좁힌 뒤 고쳤다.

증상원인조치
회원가입 401
Www-Authenticate: Bearer		Base URL에 버전 경로(/api/v1) 누락 — 매칭되는 라우트가 없어 인증 필요 응답으로 폴백xcconfig의 API_BASE_URL에 /api/v1 반영
그룹 생성 400요청 필드가 groupName이 아니라 nameCreateGroupRequestDTO 필드명 수정
그룹 생성 응답 불일치응답 필드가 invitationCode가 아니라 inviteCodeCreateGroupResponseDTO 필드명 수정
그룹 목록 디코딩 실패photos/participateMemberCount/joinedDate가 응답에 없고 todayPhotoUploaderCount만 존재GroupSummary 재설계, Home UI(아바타 스택) 단순화
참여 화면 전환 안 됨전용 join 엔드포인트가 없는 게 아니라, 조회와 같은 경로를 POST로 호출하는 게 참여 처리GroupTargetType.join 케이스 추가

04 게스트 인증은 이렇게 돈다

회원가입은 로그인과 역할이 다르다 — 로그인은 기존 providerToken으로 같은 계정에 돌아가는 것이고, 회원가입은 매번 새 계정이어야 한다. 그래서 가입 직전에 기존 토큰을 지운다.

sequenceDiagram
    participant VM as NicknameViewModel
    participant UC as SignUpUseCase
    participant GTS as GuestTokenStore
    participant Repo as AuthRepository
    participant DS as UserDataSource
    participant Server as 서버

    VM->>UC: execute(nickname)
    UC->>GTS: clear()
    Note right of GTS: Keychain에서 기존 UUID 삭제
    UC->>GTS: fetchOrCreate()
    GTS-->>UC: 새 UUID (Keychain에 저장)
    UC->>Repo: signUp(provider: .guest, token, nickname)
    Repo->>DS: register(dto)
    DS->>Server: POST /api/v1/user/register
    Server-->>DS: userId, accessToken, refreshToken
    DS-->>Repo: AuthSessionResponseDTO
    Repo-->>UC: SignUpResponse

05 토큰 3개, 저장 위치가 다 다르다

이름은 비슷해 보여도 역할이 다르다. providerToken을 잃어버리면 계정 자체를 되찾을 수 없어서 Keychain 영속화가 필수고, accessToken은 수명이 짧아 굳이 영속화하지 않아도 된다.

토큰저장 위치역할
providerToken (게스트 UUID)Keychain계정의 "신원". 로그인 시 이 값으로 같은 계정에 재진입
accessToken메모리만매 요청 인증 헤더. 수명 짧고 자주 교체됨
refreshTokenKeychain (이번에 추가)accessToken 재발급용. /auth/reissue마다 rotation
